# PDM MEMS 与 MAX9814 模拟音频前端：语音对讲选型

核验日期：2026-09-22。验证等级：官方资料与源码核验，`cataloged`；没有完成上板采集、
声学、AEC 或持续运行验证。本页只保存公开产品事实和通用工程建议。

## 选型结论与身份

对于支持 PDM 的数字主控，近距离语音对讲优先评估 **M5Stack Unit Mini PDM U089**：采集链路
直接进入数字域，可减少外置模拟放大器、ADC 和模拟布线的集成工作。**MAX9814 模拟模块**
适合已经具备合适音频 ADC/codec 输入、需要外置驻极体麦克风和硬件 AGC 的系统。
这是工程选型判断，不是两块实物的音质测评；不能仅凭数字接口断言任何环境下音质都更好。

- [M5Stack 产品记录](../../catalog/vendors/m5stack/products/unit-mini-pdm-u089.yaml)：
  精确产品为 U089，内部 SPM1423HM4H-B；“PDM MEMS、按时钟自动切换状态”的官方描述与此对应。
  采购仍应核对 SKU，不能只凭泛化标题认定型号。
- [ADI MAX9814 记录](../../catalog/vendors/analog-devices/products/max9814.yaml)：记录的是
  放大器 IC。未经厂家原理图确认的第三方模块，其咪头、PCB 修订、接线和整板性能保持未知；
  不将其认定为 ADI 评估板或其他厂商的同外观产品。

## 区别

| 项目 | M5Stack U089 | MAX9814 模拟麦克风模块类 |
| --- | --- | --- |
| 前端 | MEMS 麦克风，内部完成数字化 | 通常为驻极体咪头加 MAX9814；具体咪头须另核实 |
| 输出 | PDM，CLK/DAT 两根信号线 | 放大后的模拟电压 |
| 主控接入 | PDM 接收与抽取滤波，输出 PCM | 先进入音频 ADC/codec，再得到 PCM |
| 自动功能 | 供电与时钟决定工作/休眠/断电状态 | 硬件 AGC，压缩过大信号并调节电平 |
| 增益 | 未发现内置 AGC 声明；需主机处理音量/动态范围 | 无压缩时 40/50/60 dB，总增益随 AGC 改变 |
| 供电 | 成品接口标称 5 V；HT7333 稳压到 3.3 V，信号为 3.3 V 域 | IC 为 2.7-5.5 V；整板范围及输出电平另核对 |
| 功耗依据 | M5 页面列 600 µA；裸麦克风手册列最大 600 µA，不能当整板实测峰值 | IC 典型 3.1 mA、最大 6 mA；整板与 ADC 另计 |
| 噪声与集成 | 减少暴露的模拟信号链，但时钟、电源、声学结构仍需设计 | 对模拟走线、供电、接地、ADC 与增益匹配更敏感 |
| 回声消除/播放 | 均未集成 | 均未集成 |

依据：[M5 中英文资料][m5-zh]、[官方原理图][m5-sch]、[Knowles 手册][spm]、[ADI 手册][max]。
未收录电商价格、店铺截图、个人订单或未核实的模块参数。

### 不可直接比较的数字

- M5 页的 61.4 dB(A) 是麦克风在 94 dB SPL、1 kHz 下的声学信噪比；Knowles Revision A
  列 61.5 dB(A)。MAX9814 的 64 dB(A) 是放大器在规定电信号与带宽下的值，包含范围不同。
- M5 页的 1% THD（100 dB SPL、1 kHz）与 MAX9814 的 0.04% THD+N（指定电输入、负载、增益
  和 AGC 条件）不是同一种整机测试，不能据此说 MAX9814 对讲更清晰。
- Knowles 原手册将 1% THD 列为该声压下的最大值，M5 页称典型值；保留来源差异，不伪造
  统一精度。距离、风噪和回声效果均需完整设备的声学测试。

## Canaan CanMV K230 V3.0 的适配判断

对应资料库中的 [Canaan CanMV K230 V3.0](../../catalog/vendors/canaan/products/canmv-k230-v3p0.yaml)。
这与 LCKFB 庐山派 K230、Lite K230D 是不同板型。

**板级资料补充：**官方 [V3.0 硬件工程][v3-project] 已提供 2024-05-09 的 7 页原理图和 PCB。
其 `Peripherial` 页与器件定义确认 MIC1 为 Goertek B4012AP422-003 驻极体麦克风、AUDIO1 为
Audio_PJ-3220 音频插座；`K230` 页有 JP1 2×20 扩展排针。来源路径、错误链接标签与文件
哈希见 [Canaan 供应商知识页](../../catalog/vendors/canaan/README.md)。此前未核对到这些
文件，不能据此称“V3.0 官方资料不全”。2026-09-22 已完成音频相关连线、BANK2 电压域与
PDM 复用审查，见 [V3.0 板卡接线档案](../../boards/canaan-canmv-k230-v3p0/README.md)。

对已有这块板的原型，建议**先验证板载麦克风与音频播放路径**，检查音质、位置和 AEC 是否
满足需要，再决定是否外置拾音模块。前文 U089 优先于 MAX9814 的判断适用于需要外置麦克风
且 PDM 连接条件满足的情况，并不表示必须额外购买麦克风。

| 层次 | 已核验事实 | 尚未证明 |
| --- | --- | --- |
| K230 音频外设 | 官方 Audio API 支持 PDM、I2S 与内部 codec；TRM 明确 GPIO26 的 PDM_CLK 和 GPIO27 的 PDM_IN0 复用 | 当前固件与应用的运行时资源冲突 |
| V3.0 硬件设计 | 官方 EPRO 确认 PDM 路线暴露在 JP1，BANK2 为 3.3 V；MIC1 为有板上偏置/耦合电路的模拟咪头 | 实物修订/装配一致性、实际电压与音频质量 |
| CanMV v1.8 | 固定提交的 `media/pyaudio.py` 有 PDM 设备输入、PCM 读取与 3A 配置分支 | 任一实际烧录镜像均具有相同行为 |
| PDM 示例 | 官方存在 `audio_pdm.py` | 示例明确以庐山派配置 GPIO，不是 V3.0 接线证据 |
| 对讲效果 | 软件提供 ANS/AGC/AEC 控制入口 | 播放参考信号、通道和延迟匹配，以及真实双讲效果 |

依据：[CanMV v1.8 PyAudio 实现][pyaudio]、[PDM 示例][pdm-example]、[K230 Audio API][audio-api]。
引用源码固定为 `c2d1f5cc994c206d0032aaf6aaf09332f3dc3c4c`，与板卡记录的 v1.8 一致。
SDK 音频实战资料中另有 PDM→I2S 回环，但其参考硬件是 EVB/音频子板，不能作为 V3.0 的
接线或验证结果。

### 建议的第一轮参数与适配检查

以下参数来自公开源码和芯片约束；排针连线已有板级文档依据，实际采音仍待验证：

1. 以 **16 kHz、16 bit** PCM 作为语音处理起点。CanMV v1.8 的 PDM 分支固定 64 倍过采样，
   对应时钟 `16000 × 64 = 1.024 MHz`，位于 SPM1423 的 1.0-3.25 MHz 工作区间。
   同一路径直接设 8 kHz 会得到 0.512 MHz，低于麦克风规格；若网络需要 8 kHz，可先在合适
   时钟下采集，再做滤波降采样。采样率不能只按主控支持列表选择。
2. 此版本以 `input_device_index=1` 选择 PDM，并通过 `channels // 2` 建立双声道组，
   PDM 分支强制 stereo。单颗 U089 应先按一组双声道核验（`channels=2`），读取第 0 组、
   确认有效左右槽，再提取单声道；直接填 `channels=1` 会使分组数变成零。
   U089 的 SELECT 在模块上接地，没有证明另一槽有有效音频，不能未经检查混合左右槽。
3. 使用 [V3.0 板卡档案](../../boards/canaan-canmv-k230-v3p0/README.md) 的独立接线依据：
   已用该板官方原理图/PCB 和 K230 TRM 核对 PDM_CLK/PDM_IN0 排针路线及 3.3 V 电压域。
   仍需核对实物修订及当前程序的引脚占用；单颗 U089 不需照抄庐山派示例的其他 PDM 数据脚。
   GPIO 编号与 JP1 物理针号不同。
4. U089 接口按官方 5 V 供电，CLK/DAT 为 3.3 V 域；与目标 PAD 电压域匹配后才连接。
   不把 5 V 电源接入信号脚。整板峰值电流和目标供电口余量尚未验证。
5. PDM 输入与播放流分开建立。源码拒绝同一个流同时设置 `input=True` 和 `output=True`；
   这不等于系统不能同时采集与播放。播放端需核实该板的 codec/功放/扬声器路径，或采用
   已验证的外部 I2S 播放链路。
6. `enable_audio3a()` 有 PDM 分支不等于 AEC 已完成。先核实固件、参考音频路径、有效通道、
   采样率和延迟，再测远端单讲、近端单讲、双方同时讲话。官方 API 对 3A 概述与 AGC 支持
   采样率的表述范围不同；首轮选用共同覆盖的 16 kHz/16 bit，不外推所有格式均支持。

**K230 选型结论：**V3.0 官方设计已确认外露且电平匹配的 PDM 路线；需要外接模块时可优先
评估 U089，其软件接入也有官方依据。如果精确板卡已有易接入的模拟音频输入，MAX9814
路径也可评估，但必须先检查 codec 的偏置与增益。不能把经过 40-60 dB 放大的输出直接
当成裸咪头接入高增益 MIC 输入。
音频相关引脚审查已完成，实机验证仍未完成，不能把 U089 表述为“已即插即用”。
板载麦克风路径应先作为现成硬件基线测试。

### 只调整拾音位置时：移出原咪头

V3.0 的 MIC1 为两脚驻极体咪头，主板已提供偏置和隔直耦合。如果主要问题是咪头距面板
声孔太远，可以先录原位基线，再拆下原咪头，用短线接回原焊盘，通常可沿用模拟采音程序。
首轮可试 5–10 cm 屏蔽线或信号/地绞合线，这是工程建议，不是最大线长规格。
具体焊盘、极性、阻容网络和恢复方式见 [板卡档案](../../boards/canaan-canmv-k230-v3p0/README.md)。

替换优先同型号 B4012AP422-003；其他驻极体咪头需核对电压、电流、负载、灵敏度和结构。
不要将原咪头与新咪头并联。U089 是数字 PDM 模块，不能焊到 MIC1 的两脚模拟接口作直接
平替；MAX9814 的放大输出同样不能当裸咪头替换。位置改善后的收音和 AEC 需在最终外壳内测试。

## AEC 原理：一个麦克风与一路播放参考即可

AEC（Acoustic Echo Cancellation，声学回声消除）不要求同一设备有两个麦克风。它需要两路
信息：**麦克风采集的声音**，以及**实际送往扬声器的播放音频参考**；第二路通常直接从数字
播放链路取得，不需要再用一个麦克风录扬声器。

以通用双端对讲为例：远端说“你好”，本端扬声器播放“你好”。本端麦克风同时收到本端用户
的回答、扬声器泄漏的“你好”、反射声和环境噪声。如果全部传回远端，远端就会听到自己
延迟后的声音。AEC 在本端发送之前估算并消除这部分播放回声。

处理过程可概括为：

1. 保留扬声器播放参考 `x`，并让它与麦克风采样时间对齐。
2. 自适应滤波器学习扬声器→空气/反射→麦克风的声学路径，包括延迟、衰减与频率变化；
   根据 `x` 生成预测回声。不能直接拿原始播放波形相减，因为回声已经被环境改变。
3. 从麦克风信号中减去预测回声：
   `发送候选音频 = 麦克风采样 - 估算的播放回声`。
4. 结合双讲检测与残余回声抑制，保留本端用户说话。它不会自动消除所有环境声，背景降噪
   和音量控制分别属于 ANS/NS 与 AGC。

两个麦克风常用于空间信息、波束成形和降噪，可以与 AEC 配合，却不是 AEC 的必要条件。
双端设备各有一个麦克风，也不代表 AEC 必须跨网络取得两只麦克风的录音才能工作：每端
使用自己的麦克风采样与本端播放参考，就可以消除本端扬声器泄漏；另一端若同样免提播放，
也应处理自己的回声。

最难的情况是双方同时说话（双讲）、设备或人移动导致声学路径改变，以及扬声器/功放削顶
导致非线性失真。参考音频缺失、取样位置不匹配或时序漂移都会降低效果。工程上应让参考
尽量反映实际播放的音量与处理结果，避免过载，并在真实外壳和目标音量下验证；仅启用
`AEC` 标志或观察 PCM 非零不能证明效果合格。

因此单颗 U089 可以作为 AEC 的拾音输入；算法、参考信号和资源调度由主控音频系统承担。
这说明单麦方案的原理可行性，并不代表 U089 + 任一 CanMV 固件已经完成 AEC 验证。

## 对讲系统的通用工程建议

以下为可迁移的工程建议，不是模块厂商承诺：

- 拾音链路为麦克风→PCM→回声消除/降噪/增益处理→编码与网络；播放链路为网络→解码→
  codec/功放→扬声器。AEC 需要取得与实际播放对应的参考音频和时序。
- MAX9814 的 AGC 会改变动态增益，在安静段可能同时抬高环境噪声；对扬声器泄漏形成的
  非线性/时变处理也可能增加 AEC 调试难度。避免未经评估叠加硬件、codec 与软件多级 AGC。
- PDM 模块的“自动状态”由时钟与供电驱动，不检测说话、不自动降噪、不切换对讲方向。
  SPM1423 在低于 1 kHz 时钟下睡眠；真正断电需要移除供电，唤醒还需预留稳定时间。
- 两者都需要合理声孔、隔振、防风与麦克风/扬声器隔离。当前未核实 U089 或未知模拟板的
  户外防水等级；外壳与声学透声防护需按安装环境设计和验证。
- 联调时记录精确板型/模块修订、固件版本、供电、距离、音量、持续时间和通过条件。
  在摄像头/KPU、显示、网络与存储的组合负载下检查丢帧、端到端延迟、削顶、噪声、AEC、
  心跳与复位；非零 PCM 只证明取到了数据。
