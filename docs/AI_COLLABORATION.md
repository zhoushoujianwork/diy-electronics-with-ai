# 人 + AI 协作方式

## 多 Agent 兼容

`.agents/` 是仓库内技能和 Agent 资源的唯一规范目录，`AGENTS.md` 是唯一规范协作说明。
`.claude` 和 `CLAUDE.md` 分别是指向它们的兼容软链接。新增或修改规则时只编辑规范源，避免
不同工具读到互相漂移的副本。其他 Agent 工具可添加自己的入口，但应引用同一规范源。

并行 Agent 应划分互不重叠的目录或文件范围；开始前检查工作树，结束时说明修改范围、验证
命令和未验证项。共享工作树中的现有改动默认属于人类或其他 Agent，不得覆盖或回滚。

## 人负责

- 最终用途、预算、安全边界和是否购买/退货；
- 实物接线、上电、焊接、测量和主观体验；
- 确认库存数量、硬件修订以及是否允许公开素材；
- 对车辆、电池、市电和大电流实验做最终安全判断。

## AI 负责

- 查阅并交叉核对官方资料；
- 建立最小 Demo、驱动、测试、构建和文档；
- 在上电前检查引脚、电平、电源预算和资源冲突；
- 从串口日志、测量结果和测试数据中定位问题；
- 明确标注“推测、编译验证、台架验证、实机验证”的区别。

## 一次实验的闭环

```text
想法 → 查询物料/官方资料 → 风险检查 → 最小 Demo → 编译
     → 人工接线确认 → 上电与持续日志 → 记录证据 → 提炼组件/项目
```

如果硬件尚未到手，工作停在 `build-verified`；等实物验证后再升级状态。失败实验应写清原因、
测量条件和下一步，不以“换个阈值试试”替代第一条致命日志或电气证据。

## 物料库

电子物料的全局数据只保存在本机 electronic-materials 数据库。项目可在 README 中列出精确
BOM，但不得复制订单号、店铺账户或原始订单证据。库中购买数量只是历史记录；只有用户确认的
盘点数量才能当作库存依据。准备退货、申请退款和已经退款必须区分。

仓库中的 `.agents/skills/diy-electronics-materials/` 是可复用的查询与维护技能，不是库存快照。
它默认连接当前用户数据目录中的数据库，使同一技能可供多个 Agent 使用而不泄露个人数据。
