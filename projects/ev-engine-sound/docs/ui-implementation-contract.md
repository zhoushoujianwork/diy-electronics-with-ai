# 2 英寸界面的设计与实现约定

2026-09-22 根据官方资料和当前源码整理。本文记录调查结论和后续实施方法；
没有修改固件、运行测试、烧录或验收新界面。

## 当前结论

屏幕选型可以承载简洁的发动机声浪控制界面。当前 320×240 横屏配置有官方示例依据，
主要问题是设计稿的信息密度，以及设计稿与固件使用了不同字体、几何与控件样式。
如果目标是保留桌面 Engine Simulator 的大量小字、复杂剖面和多栏仪表，则需要重新
安排页面层级，或另行评估更大尺寸/更高分辨率的硬件；单纯把桌面图缩小不会解决可用性。

准确的尺寸、来源冲突和坐标关系见 [板卡显示档案](../../../boards/lckfb-szpi-esp32-s3-va/display.md)。
2.0 英寸屏的显示区估算约 40.6×30.5 mm，不是整机的 69×41 mm。

## 已发现的设计到实现差异

| 项目 | 设计预览 | 当前固件 | 影响 |
| --- | --- | --- | --- |
| 发动机结构 | Pillow 贴上游官方截图 | `powertrain_canvas.c` 画简化几何 | 几何、细节与动画不是同一个对象 |
| 字体 | SFNSMono、4.5–7 px 为主 | LVGL Montserrat 8/10 等及自绘 5×7 字 | 字宽、基线、行高、风格均不同 |
| 栅格化 | 4 倍绘制后 BOX 缩小，素材经 LANCZOS 缩放 | 整数像素 RGB565 绘制 | 斜线、细节和灰阶表现不同 |
| 滑块 | 4 px 轨道、矩形把手 | 12 px 对象，保留默认主题圆角等属性 | 视觉尺寸和样式不同 |
| 网页交互 | PNG 加 HTML/CSS/JavaScript 模拟 | LVGL 事件和项目状态机 | 页面可操作不表示固件视觉或行为一致 |
| 完整预览覆盖 | 独立绘制完整 320×240 设计稿 | 电脑 C 工具只共用 320×108 中部画布 | 顶栏、选择区、油门及设置没有整屏同源预览 |

源码入口：[`render_firmware_ui_v2.py`](../tools/render_firmware_ui_v2.py)、
[`ui-preview.html`](ui-preview.html)、[`powertrain_canvas.c`](../core/powertrain_canvas.c)、
[`board_ui.c`](../firmware/config/boards/lichuang_szp/board_ui.c)。

0.4.1 工作区将多处 12 px 字体调为 8/10 px，只解决部分拥挤，不能完成设计还原；
更小的字体还可能使 2 英寸真屏更难读。当前剖面始终画两组缸体，缸数主要影响标注和
点火灯，不能把它称为每种发动机的完整结构模拟。

## 常用的嵌入式 UI 交付流程

1. **先冻结硬件约束。**记录逻辑画布、方向、物理显示区、触控方式、颜色格式、
   显示带宽、字库与内存预算。约束改变时先评估设计，不在烧录阶段临时缩放。
2. **按实际像素设计页面。**设计工具可以用 Figma、LVGL Editor 或兼容版本的
   SquareLine Studio，也可以直接写 LVGL；工具名称不决定还原度。主画布始终是
   320×240，放大只用于检查像素。设计阶段就选定最终可分发的字体和实际字形。
3. **交付组件与状态规范。**用明确的坐标/尺寸、间距、字号/行高、颜色、图标和
   按下/禁用/展开等状态描述每个组件；同时写清命中区、手势、数值范围和计时规则。
4. **共享最终实现。**把页面创建、样式和状态更新从 ESP-IDF 驱动中拆出，电脑与板端
   编译同一份 LVGL 页面和绘图代码；板端负责 LCD/触摸/音频，桌面端接模拟输入，默认
   不接音频输出。设计素材转换后两端共用，不再用另一套 Python/CSS 重画“最终预览”。
5. **按相同状态审查完整画面。**锁定 LVGL 版本、字体、主题、RGB565、画布尺寸、
   发动机/排气/转速/动画相位，导出整屏快照。检查裁切、对齐、默认样式和命中区。
   原始 320×240 用于像素审查，整数倍近邻放大用于看细节。
6. **区分像素一致与实物体验。**电脑屏上的 320 像素不等于 40.6 mm；需要经标尺校准
   的物理尺寸预览，或按正确比例打印。后续只有在恢复硬件验证时，才在静音下确认真屏
   可读性、触摸、旋转与颜色；声学验收单独安排。当前用户要求停止测试，停在资料阶段。

生成代码工具同样需要检查所支持的 LVGL 版本、字体资源和自定义绘制能力。现有依赖锁
使用 LVGL 9.5.0 / esp_lvgl_port 2.9.0，官方板卡教程是 LVGL 8.3.11，不能混用 API。
运行相同 LVGL 软件绘制代码能显著缩小数字画面的差异，但无法模拟背光、盖板、视角和
触摸手感，不能承诺电脑与物理 LCD 在所有感知指标上完全一致。

## 本项目建议采用的尺度

以下是下一版设计起点，尚未实现，也不是强制行业标准：

- 主要标签从 12–16 px 起，转速等重点数字可用 20–28 px；减少标签数量，缩写只在
  不影响理解时使用。不要用 4.5–8 px 小字承担必要操作提示。
- 主要触摸命中区以 48–64 px 为起点；视觉轨道可以细，实际命中区要大且不互相重叠。
  不把普通电容屏的裸指操作能力外推为手套支持。
- 主屏优先保留转速、发动机/排气选择、油门；发动机与排气可以保留双栏构图，但减少
  小标题、装饰文字和波形。若剖面仍看不清，优先给主视觉更多空间或分屏查看。
- 三个设置不要挤在 112 px 高度里以 27 px 行距排列；可以保留下拉入口，展开后使用
  更大的设置区域，或一次调一个参数。
- 状态、倒计时和读数来自共享状态接口；设计稿固定写死的 4200 RPM、车型文字和
  计时过程不能充当固件逻辑验收结果。

## 后续实施的完成条件

- 字体、图标、机械绘图和所有控件拥有共同来源；设计所需细节应在共同实现中完成，
  不能只把旧简化固件截图改称“设计已对齐”。
- 首屏、按住油门、收油、设置展开和五种排气都能由同一份页面代码在电脑生成全屏图。
- 预览明确标注“概念设计”“共享代码渲染”或“实机照片”；保留版本与状态参数。
- 精确物理尺寸和实机可读性仍未验收时，明确保留待确认项，不升级项目状态。
