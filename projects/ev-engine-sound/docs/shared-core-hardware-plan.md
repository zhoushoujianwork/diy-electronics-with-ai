# 共用声浪核心板：车载与玩具版本方案

更新：2026-09-24。阶段：需求与架构草案，尚无自研板原理图、PCB 或新增实机验证。
现有 `hardware-verified / partial` 仅适用于[已记录的开发板验证范围](validation.md)。

## 已确认的产品方向

- 自己设计 PCB，复用现有程序化声浪合成核心，作为立创开源七周年的开源项目方向。
- 共用一块声浪核心板，提供 **3.5 mm AUX 音频输出和蓝牙音频输出**。
- 车载版优先服务电车场景，首个适配目标是 **小鹏 X9**；车内优先蓝牙播放，争取通过
  OBD 直插读取加速踏板数据。X9 的年款、动力版本和车机软件版本尚未确认。
- 后续玩具安装版使用外接电子油门手把，支持外接电池模块和音响。

“共用核心”包括声浪算法、参数、控制模型和核心 PCB；蓝牙处理器、车载接口板和
电池模块可以分工，不要求把全部功能压进同一颗芯片。车辆适配结论按车型/年款/
软件版本记录，不承诺所有电车通用。

## 推荐硬件分工

| 模块 | 负责的工作 | 两种版本的复用方式 |
| --- | --- | --- |
| 声浪核心板 | ESP32-S3 主控、程序合成、参数存储、音频路由、按键/状态灯、升级调试 | 完全共用；显示屏作为可选接口，声音功能不依赖屏幕 |
| AUX 输出电路 | I²S DAC、音量/静音、接口保护、3.5 mm 线电平输出 | 共用；接车机 AUX、有源音响或外部功放 |
| 蓝牙发射电路 | A2DP Source、PCM 缓冲、编码、配对和重连 | 共用；优先验证可编程原版 ESP32，保留专用音频模块路线 |
| 车载接口板 | 车型数据接口、总线保护、车载低压电源转换、休眠与唤醒 | X9 版配装，玩具版不需要；是否可以 OBD 直插须实测 |
| 手把接口 | 独立电子手把供电、信号调理、采样与标定 | 玩具版及桌面验收使用；可以替代尚未适配的车辆数据输入 |
| 外接电池模块 | 充电、保护、升降压、欠压关断、稳压供电 | 玩具版配装，输出匹配核心板电源规格 |
| 外接音响/功放 | 把线电平音频变为扬声器驱动 | 有源音响自带；裸扬声器必须另配功放 |

以上是功能分工，最终可以把主控、DAC 和蓝牙模块放在同一块核心 PCB。车载接口板
保留独立边界，避免玩具版承担车载供电、总线和车型适配的全部成本。

两条使用链路：

- **X9：**车辆诊断接口 → 车型适配 → 共用声浪核心 → 蓝牙发射 → 车内音响。
- **玩具：**电子手把 → 输入调理 → 共用声浪核心 → AUX/蓝牙 → 有源音响；外接电池
  模块供电。若安装裸喇叭，则增加功放并单独核算功率、温升和电池续航。

## AUX 与蓝牙方案

**AUX 定义为音频输出。** 初版建议采用 3.5 mm TRS 线电平接口，单声道合成音频
复制到左右声道。接口输出电平、负载、静音和插拔爆音应按实际接收端验证。AUX 不
直接驱动裸喇叭，也不把现有板卡的扬声器功放输出接到车机 AUX。

[TI PCM5102A][dac] 可作为 DAC 候选：厂商列出 I²S/PCM 数字输入、2.1 Vrms 线电平
输出及最低 1 kΩ 负载。2.1 Vrms 是器件能力，不能直接当作所有车机的合适输入幅度；
应留增益/衰减与静音设计。该器件尚未选定，封装、供电、外围和温度等级需按实际
料号审核，不能由系列宣传推断整板适合车规环境。

**蓝牙必须实现 A2DP Source（发射端）。** ESP32-S3 只有 BLE，不能通过配置开关变为
普通车机所需的 Bluetooth Classic A2DP 音源。现有[蓝牙选型研究](../../../docs/research/bluetooth-a2dp-source-selection.md)
已核对两条候选路线：

| 路线 | 优点 | 在落板前必须解决的问题 |
| --- | --- | --- |
| ESP32-S3 + 原版 ESP32 音频协处理器 | 保留 S3 上的声浪/UI，实现与固件可开源，角色分工明确 | I²S/PCM 传输、采样率转换、SBC 编码、配对、队列和实际延迟 |
| ESP32-S3 + BM83SM1-00TA | 专用音频模块；厂商说明 Audio Transceiver 固件支持 Source | 精确固件及再分发条件、供电、时钟方向、UART 控制和车机兼容性 |

推荐先验证第一条，再决定核心 PCB 上的具体模块。用单颗原版 ESP32 同时合成和发射
可作为降成本备选，但现有 S3 的 UI、音频和任务性能证据不能直接沿用，须重新验收。

现有核心常用 32 kHz 单声道，A2DP 端需要按协商格式转换采样率/声道，不能把现有
PCM 原样塞入任意发射模块。DAC 和发射端共用 I²S 时必须确认主从、格式和时钟；
不能把两个时钟输出直接并联。外接板的 I²S 应保持短线，不能作为车内长线连接方案。

初版按 **AUX、蓝牙可选择输出**设计，双路同步播放留待时钟、缓冲和延迟验收后再
开启。蓝牙断开时不自动把声音切到未知外设。音频路由和静音不应阻塞串口、状态灯
或声浪状态更新。

## 小鹏 X9 与 OBD 直插的边界

**OBD 是诊断/数据接口，标准 OBD 不提供车内音响的音频输入。** 即使最后做到一个
OBD 插头供电并取数，声音仍要通过独立蓝牙链路发送到车机。OBD 直插是希望实现的
安装方式，不是已经验证的 X9 功能。

| X9 适配问题 | 当前结论 |
| --- | --- |
| 诊断口位置、针脚、供电及可访问总线 | 未核验，不能按其他车型照片或通用插座外观接线 |
| 加速踏板、车速、挡位等数据 | 未取得可核验的 X9 标准 PID 支持表、厂家诊断定义或 CAN 报文映射 |
| Classic CAN / CAN FD / 其他诊断链路 | 未确认，不根据“新能源车”或 OBD 外形猜测 |
| 蓝牙播放 | 用户选择的输出方向；尚未验证 X9 对独立 A2DP Source 的配对与播放 |
| 同时连接手机、导航提示和来电 | 待实测；车机可能只允许一个媒体音源，不能承诺和手机音乐混音 |
| 停车后的取电与休眠 | 待测；不能默认诊断口随锁车断电，需防止持续唤醒或消耗车辆低压电池 |

本轮查阅了[小鹏官网][xpeng]、[官方常见问题][xpeng-support]及官网链接的
[维修信息入口][xpeng-repair]，未从所读取的公开页面获得 X9 踏板协议或接口接线依据。
未访问账户内维修资料，也未向车辆发送任何诊断请求。此结论表示**尚未核验**，不
等同于 X9 没有相关接口或数据。

通用 OBD 资料将 `Throttle position` 与 `Accelerator pedal position` 列为不同参数
（例如 PID `11` 与 `49/4A/4B`），并注明请求是否得到响应取决于车辆是否支持。
不能把节气门开度直接当作电车踏板位置；标准存在某个 PID 也不表示 X9 实现了它。
这部分参考 [CSS Electronics 的 OBD PID 说明][obd]，属于工具厂商资料，不是小鹏
授权的协议或 X9 兼容性证据。

车型验证按以下次序推进：

1. 确认年款、动力版本、车机版本及厂家接口资料，再确认物理口、电压、针脚和总线。
2. 先做真正的监听模式验证；硬件支持静默/禁止发送，不发送 ACK、错误帧或诊断请求。
   网关后可能没有可监听的踏板广播，不能把“接收到报文”当作已经找到踏板信号。
3. 若需读取诊断数据，只使用有依据的受限读取请求，并限制频率、超时和重试。
   **读取型诊断也会向总线发包**，与纯监听不同；产品不提供车辆控制、刷写、编码或
   故障清除功能。不扫描猜测控制报文，也不旁路防盗/诊断网关。
4. 用可追溯来源与静止条件下的操作对照验证信号范围、刷新率和失效值；确认对车辆
   无异常影响后才进入后续受控验证。不接管或改动原车加速踏板线路。

ESP32-S3 自带 TWAI 需要外部收发器，而且**不支持 CAN FD**。[Espressif 文档][twai]
明确 FD 帧会被其解释为错误。因此在 X9 总线类型确定以前，不画成“S3 + 任意 CAN
收发器即可”。若需要 CAN FD，必须采用支持该协议的控制器和收发器，或使用适配
模块。接入已有车辆总线时不默认增加 120 Ω 终端；台架终端应可断开。

## 接口、电源与输入契约

以下是设计目标，尚不是可接线的针脚表。

| 接口 | 初版约束 |
| --- | --- |
| 核心电源 | 优先统一为稳压 5 V 输入，再生成所需电源轨；容差、峰值电流和连接器额定值待功耗预算冻结 |
| 车载供电 | 车载低压侧 → 保险/限流、反接、浪涌/ESD、滤波、降压 → 核心板；不连接动力高压，额定范围按实车资料确定 |
| 电池模块 | 按明确的电芯串数和类型设计保护、充电、升降压及欠压关断；不把裸电池或任意“电池模块”直接接核心供电口 |
| 多路供电 | USB、车辆电源和电池之间有电源路径选择/防倒灌，避免彼此回充；USB 调试时重新核对接地路径 |
| 手把输入 | 明确选定手把型号、供电和信号范围后设计分压/缓冲、滤波和保护；常见 5 V 手把不能默认直接接 3.3 V ADC |
| 车型数据扩展 | 可更换接口板；逻辑电平、隔离、数据协议及长线收发器由选定方案确定，避免 MCU GPIO 直接接汽车总线 |
| AUX | 线电平 L/R/GND，接口 ESD、静音及接地噪声评估；有源音响与外部功放单独供电核算 |

接口使用有方向和防误插的连接器，车电、手把、电池不能共用容易误插的定义。车型
接口评估总线/电源隔离，尤其是车载供电、USB 调试和模拟音频形成多个接地路径时。
蓝牙天线净空、开关电源、DAC 模拟回路和高电流功放的布局分别处理。

软件把 OBD、手把和屏幕操作统一转换为“输入来源、时间戳、有效性、0–1 踏板量”；
车型可另带车速、挡位等有明确有效性标记的字段。现有 `ev_control_t.throttle` 已是
0–1，可以复用，但目前没有这些外设驱动和失效管理层。

- 一次选择一个油门来源，切换时先回零；不把车辆踏板与手把取最大值混用。
- 手把先标定零点/满量程并检测断线、短路、越界；故障进入零油门并渐变静音。
- 车辆数据过期、模块掉线或总线异常时退出联动，不保持最后一次大油门。
- 车辆踏板驱动的是**虚拟发动机**；纯电车电机转速不能不经模型就当成内燃机 RPM。
- 数据采集、蓝牙重连、日志与合成任务分离；新增任务明确栈预算并在并发负载下测
  高水位。指示灯、静音和心跳不得依赖蓝牙或总线阻塞调用。

## 打样前的验证顺序

1. **先做音频链路 Demo：**现有声浪核心 + 候选发射器，实际验证 X9 配对、播放、
   断连恢复、手机/导航/来电切换；测量手把动作到车内出声的端到端延迟。
2. **再做车型数据 Demo：**确认物理接口与协议，验证踏板信号、刷新率、断线回零、
   总线状态和停车休眠。车型不通时，保留手把版本，不把猜测固化进 PCB。
3. **手把 + AUX + 电池 Demo：**验证模拟输入量程、断线处理、音频电平/噪声、充放电
   与多路供电切换。蓝牙适合无线使用，AUX 保留为低延迟基线。
4. **冻结首版原理图与 PCB：**根据 Demo 结果选择精确料号、供电预算、连接器和
   天线位置，加入活动七周年 Logo，完成 ERC/DRC、BOM、制造及开源材料。

这些是后续计划，还没有创建或宣称通过对应 Demo。每个不确定组合开始实施时按
仓库规则建立独立 `demos/<slug>`，保存硬件版本、固件提交、供电、持续时间、判据和
脱敏结果；不在 Git 中保存 VIN、行程轨迹或完整车辆原始日志。

下一次选型所需信息：X9 年款/动力版本/车机版本、手把精确型号、玩具音响是否有源、
电池规格和目标续航、是否要求 AUX 与蓝牙同时发声。未明确前不冻结针脚或下单。
