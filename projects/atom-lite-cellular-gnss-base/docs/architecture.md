# 系统架构与设计决策

## 功能划分

1. ATOM Lite：启动流程、模块控制、定位数据校验、上报调度、按键/LED 与调试。
2. 蜂窝通信：Tiny ML307R-DL 作为第一轮候选，负责 Cat.1 数据连接。
3. GNSS：第一轮建议使用独立接收器；Tiny 的当前商品资料未证明卫星定位功能。
4. 电源：Type-C 输入，按各电压域稳压/分配，处理浪涌、ESD、储能和多输入防倒灌。
5. MotoBox：认证接入、位置/状态接收与设备绑定；需单独开通设备凭据。

网络实现比较两条路径：modem AT 提供 MQTT/TLS，或支持时以 PPP 接入 ESP-IDF 网络栈。
选择前验证实际模块固件、TLS 证书/主机名检查、MQTT QoS、URC 处理和内存峰值；不预设二者都可用。

## PCB 功能块草案

| 块 | 要表达的电路 | 定值/封装前缺少什么 |
| --- | --- | --- |
| Type-C 输入 | CC 检测/受电、VBUS 保护与供电分配；数据是否引出单独决定 | 电流需求、连接器型号及 footprint；5.1 kΩ Rd 只表明受电端，不能保证电源提供 3 A |
| 主控堆叠接口 | ATOM 底部供电、GND、UART/控制线 | 原理图与连接器 Pin 1、坐标、接触长度、额定电流 |
| Tiny 接口 | VIN/BAT、EN、UART、GND；明确输入输出和上电顺序 | 该核心板 VIN/BAT 范围、是否有稳压/电平转换、EN 极性、UART 域 |
| GNSS 接口 | 独立 UART 与电源；后续可改为板载接收器 | 精确方案、天线供电、接头和带宽、引脚冲突 |
| 调试与测试 | GND、输入与各电源轨、UART、EN/复位测试点 | 最终网络；测试点必须在装配后可接触 |

所有电源和信号网络当前只是功能关系；未核实的引脚保持未分配，不能用 NC 掩盖缺失资料。
BAT 暂不接电池，也不与 VIN 短接。不得凭 AT 指令相似性推断 Tiny 与 M5 U204 的电气接口相同。

## 机械与 RF

- 20 mm 板放进 24 mm 外轮廓，居中名义单边余量 `(24−20)/2 = 2 mm`，还需扣除壳壁和装配间隙。
- 商品另一边标注 19 mm，对应名义余量 2.5 mm；封装暂按实测较大的轮廓评估风险，不据此冻结生产板框。
- 若 6P 为单排、节距 2.54 mm，首末孔中心跨度是 12.70 mm；这不是连接器总长，也不能确定孔坐标。
- 6 mm 商品厚度与 9.6 mm 主机外壳高度不能直接相加得整机高度；还有载板、配对连接器、底壳及净空。
- ATOM 底部总线与 Tiny 6P 是不同连接器；不能把 Tiny 的六脚定义套给 ATOM。
- 天线与接地/金属件的间距按各天线和模块的官方参考设计确定，不能以一个通用全层挖空规则代替 RF 设计。
- 同机包含 LTE、GNSS、Wi-Fi/BLE 时要评估天线隔离、LTE 发射干扰、开关电源噪声和 GNSS C/N0。

## 固件职责与可观察性

计划用状态机管理 SIM、注册、数据会话、TLS/MQTT 和 GNSS，每步有超时、重试间隔与失败原因。
LED/按键/心跳避免等待 modem 或存储锁；UART 接收、解析与上传采用有界队列。
每个新建或修改的 FreeRTOS task 根据最大调用路径估算栈，并在 TLS 建链、弱网重试、GNSS 输入与
实际启用的 BLE/存储负载下测高水位；此阶段没有创建任务，也没有可报告的栈验证结果。

## 成本比较方法

不把 M5 成品单元与裸模组价格直接相减作为“省下的成本”。比较同一范围：模块、SIM、天线、
PCB/SMT/插件、连接器、外壳、线材、测试、返修损耗与物流；网络服务单独列持续费用。
现在没有经过核实的报价，Tiny 宣传赠送流量也不作为长期运营预算。
