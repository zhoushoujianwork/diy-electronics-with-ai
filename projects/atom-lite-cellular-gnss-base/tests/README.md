# 验证计划

本目录目前只有测试计划，没有固件/硬件通过记录。[validation.md](../docs/validation.md) 是实际结果入口。
文档与 JSON/CSV 可解析只证明记录可读，不证明 PCB、电源或通信功能。

## 实施后添加的自动检查

- GNSS：有效/无效 NMEA、校验和、RMC/GGA 时间匹配、陈旧 fix、无定位状态；复用既有测试经验。
- modem：AT 应答与异步 URC 交错、半帧、超时、SIM 异常、掉线重连、退避和队列上限。
- 上报：时间/坐标来源标记、设备认证、TLS 验证、MQTT ACK 与离线补传顺序。
- 构建：固定 ESP-IDF 与目标 `esp32`，检查配置不依赖 StickS3 的 PSRAM/屏幕/音频。
- 第二主机：实现后另建 StickS3 `esp32s3` 构建与板级供电配置；协议测试可复用，构建/实机结果分别记录。

## 实机矩阵

每轮记录硬件/模组修订、固件提交、供电与线材、SIM/运营商（不公开号码）、天线位置、持续时间和阈值。

| 阶段 | 检查 | 预期证据 |
| --- | --- | --- |
| 接线前 | Pin 1、通断、供电范围、UART 域与 EN | 标注清晰的脱敏照片/测量表和官方资料 |
| 首次供电 | 限流启动，各轨电压、峰值与压降、异常温升 | 波形与记录；阈值按器件手册制定 |
| Type-C | 正反插、不同合规电源/线材、ATOM 调试口同时连接 | CC/可用电流与防倒灌测量；不默认所有口都可提供 3 A |
| 固件启动 | task 创建、reset reason、连续心跳、栈/堆余量 | 持续串口日志；检查 stack overflow/Guru Meditation/panic/USB 重连 |
| 联网定位 | 注册、TLS/MQTT、室外 GNSS fix、后端 ACK | 模块日志 + GNSS 质量 + 服务端回执；地图只作辅助 |
| 恢复与负载 | 20 次重启、3 次断网、2 小时运行（初验提议） | 每次耗时、错误、队列与丢帧、最低栈水位；非量产可靠性承诺 |
| 结构射频 | 叠装/插拔/紧固、LTE 发射下 GNSS 与 Wi-Fi/BLE | 实物干涉检查、接收质量/重启/温升对比 |
| 打印外壳 | 按材料/方向/公差记录装配、插拔受力、变形和热稳态 | ATOM 与 StickS3 分别记录壳体修订；外壳承重，排针不作唯一固定 |
| StickS3 变体 | Hat2 针号/方向、5V_IN 输入、EXT_5V 模式、USB 同插及拔电行为 | 独立供电矩阵与 UART/电池倒灌测量；不由 ATOM 验证外推 |
| 双串口 | GNSS 连续输出时 4G 注册/上传/断线重连；分别拔除外设 | NMEA 校验失败、UART 溢出、AT/URC 丢失、队列峰值及心跳；两路 TX 不并联 |
| 试产 | 治具、烧录、凭据配置、每板合格/失败记录 | 批次统计与返修原因；数量在试产前确定 |

若最终没有 SD，就不虚构 SD 日志；若引入 SD，刷机后同时检查 SD 启动日志与串口首个致命错误。
任何新增/修改任务都先按最大调用链估算栈，再在实际启用的 LTE/GNSS/BLE/存储负载下测高水位。
